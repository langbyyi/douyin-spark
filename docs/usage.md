# 使用指南

## 前置条件

完成 [安装](../README.md#快速开始) 和 [配置](configuration.md) 后执行本节命令。示例要求项目虚拟环境已激活；独立调用入口为 Windows 的 `.venv\Scripts\spark.exe` 或 Linux 的 `.venv/bin/spark`。

`main` 表示账号内部标识。初始配置不包含账号；账号可通过控制面板注册，或在配置文件中显式定义。

## CLI 命令

| 命令 | 执行语义 |
| --- | --- |
| `spark doctor` | 检查依赖、浏览器、配置及目录权限，不启动浏览器或创建数据目录 |
| `spark doctor --feature gui` | 将 GUI 运行依赖纳入必需项检查 |
| `spark doctor --feature mcp --json` | 检查 MCP 依赖并输出 JSON 诊断结果 |
| `spark login main` | `SPARK_ENV=cloud` 时默认采用 QR 模式；其他环境采用窗口模式 |
| `spark login main --mode web` | 启动临时网页登录服务，支持二维码及平台要求的短信验证 |
| `spark check --account main` | 验证登录状态、账号身份和出口 IP，不提交消息 |
| `spark disable main` | 停用账号并阻止后续发送，不启动浏览器 |
| `spark enable main` | 启用存在登录记录的账号，不启用每日计划 |
| `spark friends --account main --json` | 读取会话；默认不修改发送对象配置；结果写入 stdout，日志写入 stderr |
| `spark friends --account main --json --save` | 使用读取结果替换指定账号的 `friends` 列表 |
| `spark run --account main --dry-run --now` | 验证会话定位，不提交消息，跳过 CLI 启动随机延迟 |
| `spark run --account main --now` | 执行单次发送，跳过当日已确认成功的对象 |
| `spark status` | 查询登录记录、当日发送账本、最近运行及运行锁状态，不启动浏览器 |
| `spark schedule` | 根据配置预览计划时间和服务启动命令，不查询实时调度器或创建系统任务 |
| `spark gui` | 启动控制面板和调度服务，默认监听 `127.0.0.1:8765` |
| `spark mcp` | 启动 stdio MCP 服务 |
| `spark password reset` | 服务停止后重置控制面板认证密码 |

全局参数位于子命令之前，例如 `spark --config /path/to/config.toml --data /path/to/data status`。`run`、`check` 和 `friends` 支持重复指定 `--account`；未指定时按命令语义处理配置账号。`pause`、`resume` 分别为 `disable`、`enable` 的兼容别名。`gui --open` 启动默认浏览器，`--no-open` 禁用该行为。

`login --timeout` 的单位为秒；`login.timeout_minutes` 及 MCP 登录超时参数的单位为分钟。`friends --sparks-only` 根据会话读取结果筛选包含火花天数的会话；与 `--save` 联用时，筛选结果将覆盖发送对象列表，空结果亦可能保存为空列表。

`--dry-run` 禁止消息提交，但仍可执行环境验证、健康状态更新、运行记录写入及历史文件清理。会话读取可更新缓存和日志。因此，定位验证与读取命令具有本地持久化副作用。

## 初始运行流程

1. 执行 `spark doctor --feature gui`，确认必需检查项通过。
2. 执行 `spark gui`，访问控制面板并完成认证。
3. 使用「添加抖音账号」完成二维码登录和平台身份验证；登录状态保存完成后，账号写入配置并启用。
4. 配置发送对象列表和消息模板，执行 `--dry-run` 并核对会话定位结果。
5. 在「计划」页面保存执行时间并启用调度，保持服务进程运行。

账号注册界面支持代理地址、环境变量名或变量引用；空值表示直接连接。代理凭据保存在配置文件同目录的 `.env`，TOML 仅保存变量引用。登录及发送使用相同的网络配置。

CLI 常规登录要求账号已在配置中定义；新账号注册参数参见 [账号登录](#账号登录)。已有账号重新登录保留原有 `enabled` 值；停用账号通过 `spark enable main` 恢复参与发送。

## Web 控制面板

| 页面 | 功能范围 |
| --- | --- |
| 概览 | 当日进度、下次执行时间、待处理账号和对象、账号管理入口 |
| 账号 | 账号注册、登录验证、环境检查、单账号发送、对象列表、消息模板及代理配置 |
| 计划 | 每日执行时间、调度开关、后续时间预览及服务状态 |
| 日志 | 运行结果、历史日志、截图及 GUI/MCP 服务日志 |
| 设置 | MCP 开关、客户端配置、通知开关、渠道凭据及通知测试 |

控制面板保存操作保留未修改的配置字段及注释。草稿仅在保存后生效；切换账号时提示处理未保存修改。消息编辑规则参见 [消息模板](configuration.md#消息模板)。实际发送操作要求确认账号及对象范围。

页头的 GitHub 入口在新标签页打开项目仓库，可查询源码、使用文档及提交问题。

### 账号生命周期

- **注册**：登录成功且状态保存完成后登记账号。取消、超时或失败不创建空账号。未登记且无登录记录的临时浏览器用户数据目录进入清理流程；已登记账号和已有登录记录的目录保留。
- **重复注册检测**：存在平台用户标识时，拒绝重复注册相同账号。用户标识不可读取时，不具备可靠的重复身份判定依据。
- **登录任务完成**：`finalizing` 表示验证和持久化阶段，该阶段不接受取消。业务状态为 `success` 后，仍需等待后台任务退出，方可启动其他浏览器任务。
- **账号注销**：「账号设置 → 删除账号」移除账号配置、发送对象列表和模板，保留浏览器用户数据、日志及账本。活动任务或未确认结果阻止注销；注销最后一个账号同时禁用调度。重新注册生成新的内部标识。

控制面板账号登录使用同源地址。二维码、截图和短信操作要求控制面板认证；内部登录服务监听本地随机端口，无需单独开放 8789。

## 账号状态与发送保护

| 状态层 | 持久化内容 | 作用 |
| --- | --- | --- |
| 账号配置 | `enabled` | 控制账号是否参与发送 |
| 健康状态 | `health.json` | 保存登录、身份和网络验证结果 |
| 发送账本 | 按日期保存的发送记录 | 控制已完成对象、重试预算和未确认结果保护 |

三类状态相互独立。启用要求存在登录记录并清除缓存的健康状态，不替代发送前验证。活动任务、未确认结果或其他进程持有运行锁时拒绝启用；停用允许在任务执行期间生效。

| 验证结果 | 发送行为 | 处理要求 |
| --- | --- | --- |
| 用户停用 | 排除该账号 | 显式启用账号 |
| 登录失效 | 阻止发送 | 在原账号环境重新登录 |
| 平台安全验证或身份不一致 | 阻止发送 | 完成人工验证或重新登录并确认身份 |
| 出口 IP 或代理配置变化 | 阻止发送 | 核对网络配置并重新建立登录基线 |
| 网络故障或健康状态文件异常 | 当前验证可能失败 | 环境恢复后由后续任务重新验证 |
| 验证通过 | 更新健康状态 | 已启用账号继续执行 |

`check` 不修改账号启用状态。用户标识不一致或不可确认时，发送流程不通过身份验证；出口 IP 一致不构成账号身份验证依据。

### 回执与重试策略

- 当日已确认成功的对象不重复发送。
- 普通失败按对象计数，每日最多 3 次尝试。
- 回执超时、发送预留未完成、回执冲突及其他未确认结果保留保护记录，不自动重发，包括跨日期情况。
- 提交后继续观测当前请求的迟到回执；仅与当前提交关联的可靠回执可更新结果。
- 账本异常阻止发送；历史清理保留未解决结果的原始账本及最新后续记录所在账本。

控制面板中的失败结果提供原因和诊断入口，原始错误信息可展开查询。环境检查不清除账本保护。消息提交成功后，账号停用仅阻止后续提交，不撤回已提交消息。

发送结果以平台消息回执为依据，平台火花天数由平台界面确认。定位验证不登记为发送成功。

## 群聊发送

`friends` 同时支持好友名称和完整群聊名称，例如 `friends = ["好友备注A", "周末小群"]`。群聊须存在于当前账号会话列表，或可通过搜索准确定位；新增对象通过「续火花对象」配置或会话读取结果添加。

发送仅使用显式配置的对象列表，不遍历群聊历史或统计成员发言。提交前后读取当前页面的消息上下文，以关联本账号的新发送请求与回执。其他成员是否发言不影响执行。

### 会话定位约束

会话定位验证名称及聊天面板标题。明确的成员人数标识不作为名称内容；平台额外追加的 `(人数)` 仅在侧栏名称一致且聊天面板确认为群聊时接受。名称原有的数字后缀保留。

可见列表中的同名对象、标题不可读取或收件人标识冲突均阻止发送。虚拟滚动列表不同页面中的同名对象不具备全局唯一性保证；发送对象应使用可区分的备注名或群聊名称。

### 结果与展示

「本次发送」仅统计当前任务新增的成功对象；当日既有成功记录列为「今日已发送，本次跳过」。跨日期后，前一日期已完成的对象标记为跨日前记录，不计入新日期的完成数量；后续任务按新日期账本处理。

会话读取结果缓存于账号的 `conversations.json`，包含可识别的头像、会话类型和成员人数。账号目录展示平台本人头像。图片缺失、失效或加载失败时采用文字占位；头像及会话类型展示不参与发送资格判定。

## 自动计划与服务生命周期

每日计划默认禁用，执行时间使用配置时区。每个数据目录由单个 GUI 进程持有调度器；CLI、GUI 和 MCP 共享运行锁。

| 情况 | 调度行为 |
| --- | --- |
| 服务启动、休眠恢复或计划重新启用 | 为当日已到期的最近时段创建补偿执行计划 |
| 多个历史时段未执行 | 不逐个补偿更早时段，不补偿前一日期计划 |
| 普通失败 | 间隔 30 分钟重试，每个计划最多 3 次尝试 |
| 任务启动失败 | 消耗尝试次数 |
| 运行资源占用 | 不消耗尝试次数 |
| 当日较新时段到期 | 替代更早且从未执行的积压时段；保留已尝试的当日重试计划 |
| 日期切换 | 取消前一日期的待重试计划，按新日期执行时间继续调度 |

当日补偿执行不受两小时延迟上限限制。已登记的有效重试计划继续执行；旧版本取消的当日计划仅在时间、时区和尝试预算仍满足条件时恢复。

新计划增加不超过 `timing.jitter_minutes` 的随机启动延迟。实际触发时间以持有调度器的控制面板「计划」页面为准；`spark schedule` 仅提供配置推算结果。独立 MCP 进程不承载调度器。

计划停用仅阻止新的触发，不取消已启动任务。控制面板页面关闭或认证退出不终止服务；`spark gui` 停止时取消所属任务、登录服务及浏览器进程。服务重启恢复已保存的调度设置。

## 面板认证

控制面板认证与抖音账号登录相互独立。未认证请求重定向至认证页面或返回 API 拒绝响应；业务写请求另需页面令牌。

初次启动未配置密码时，终端输出一次 32 字符随机密码。密码以带随机盐的 PBKDF2-HMAC-SHA256 哈希持久化至 `data/gui-auth.json`，迭代次数为 600,000。POSIX 文件权限为 600；Windows 创建认证文件时移除继承 ACL 并授权当前运行账号。初始化要求文件系统支持硬链接和权限控制。

### 密码管理

- `SPARK_GUI_PASSWORD` 仅用于首次初始化，最少 8 个字符；进程环境变量优先于 `.env`。
- 认证文件建立后，环境变量修改、清空或移除均不覆盖已保存密码。
- 控制面板修改密码要求当前密码及新密码确认。修改后撤销当前服务的所有认证会话，不修改抖音登录状态或调度配置。
- 密码重置要求服务已停止，使用 `spark password reset` 交互输入两次新密码；非交互环境使用 `spark password reset --random`，生成值仅输出一次。
- 自定义配置或数据目录需使用对应全局参数，例如 `spark --config C:/spark/config.toml --data C:/spark/data password reset`。
- Docker 快速部署依次执行 `docker compose stop local`、`docker compose run --rm local password reset --random`、`docker compose up -d local`。HTTPS bridge 部署将服务名 `local` 替换为 `spark`。
- 旧认证机制迁移时保留原有效密码；迁移完成后以持久化认证文件为唯一密码来源。

认证文件损坏导致服务启动失败；恢复通过密码重置流程完成，不使用环境变量绕过异常文件。

### 会话与访问控制

会话存储于服务内存，空闲 30 分钟或累计 12 小时后失效。退出认证或服务重启撤销相应会话。密码尝试限制为单来源每分钟 5 次、服务整体每分钟 20 次；超限响应为 HTTP 429 并包含 `Retry-After`。

认证 Cookie 使用 HttpOnly 和 SameSite=Strict，HTTPS 请求启用 Secure。URL 不接受认证密码或会话令牌。默认回环监听支持 HTTP；非回环监听要求 HTTPS，参见 [反向代理配置](cloud.md#https-反向代理)。

## 账号登录

本地窗口模式：

```bash
spark login main --mode window
```

独立网页登录模式：

```bash
spark login main --mode web
```

CLI 新账号注册支持代理变量名或引用，不接受直接代理 URL：

```bash
spark login account_new --mode web --new-account --proxy-ref MAIN_PROXY
```

代理变量在配置文件同目录的 `.env` 中定义。网页登录使用该账号的持久化浏览器用户数据目录和代理配置。网页登录默认无头，后续发送、检查及会话读取由 `browser.headless` 独立控制。云端默认 QR 模式要求 Server酱凭据或有效的 `public_url`；网页登录应显式指定 `--mode web`。

服务地址格式为 `<public_url>/login/<随机令牌>`；未指定前缀时，按监听地址生成 HTTP 地址。随机令牌为临时会话访问凭证，禁止公开传播。通知发送要求渠道已配置且通知开关启用。

| 登录阶段 | 处理方式 |
| --- | --- |
| 二维码验证 | 展示二维码并识别扫描和移动端确认状态 |
| 短信验证 | 根据平台流程收集手机号和验证码；绑定号码由平台指定时不重复收集完整号码 |
| 平台安全验证 | 使用本地窗口或 noVNC 完成人工验证 |
| `finalizing` | 验证运行环境并保存登录状态，不接受新短信、验证码或取消请求 |

配置 `SPARK_VNC_PASSWORD` 且未显式设置 `login.headless` 时，网页登录使用有头模式并可提供 noVNC。`login.headless = true` 禁用 noVNC。远程验证入口参见 [登录与手动命令](cloud.md#登录与手动命令)。

保存登录记录包含出口 IP 验证。代理不可用时终止登录，不降级为直接连接。界面和日志展示脱敏代理信息。

独立登录链接默认有效 10 分钟。登录流程退出后关闭浏览器；HTTP 服务可保留约 6 秒用于结果查询，随后释放端口。单会话短信发送最多 3 次，间隔至少 60 秒；验证码提交最多 5 次。日志仅保存手机号前三位及后四位，不保存验证码。

登录状态保存阶段的临时 HTTP 写请求返回 HTTP 409。业务终态与后台进程退出分开表示，后续浏览器任务要求前一任务完成资源回收。

## 退出码

| 退出码 | 含义 |
| --- | --- |
| 0 | 执行完成、无待发送对象，或 `run` 因运行锁占用跳过 |
| 1 | 部分失败、运行异常或必需环境检查失败 |
| 2 | 登录失败、登录状态失效、出口 IP 变化或参数解析错误；错误来源以 stderr 为准 |
| 3 | 平台安全验证或风险控制状态 |
| 64 | 配置或认证错误，密码重置输入无效或取消 |
| 69 | GUI/MCP 依赖不可用或 MCP 启动开关禁用 |
| 73 | 数据目录创建或写入失败，或 GUI 启动发生操作系统错误 |
| 75 | 运行锁或 GUI 服务锁占用，或服务运行期间请求密码重置 |

## 故障排查

### 诊断顺序

1. 执行相应功能的 `spark doctor`，核对依赖、浏览器、配置及文件权限。
2. 查询任务结果和 `data/runs/<运行编号>/run.log`，按账号和发送对象定位失败阶段。
3. 查询 GUI/MCP 服务问题时，使用 `data/logs/gui.log` 或 `data/logs/mcp.log`；控制面板日志页面及 MCP `logs` 工具支持选择服务日志。
4. 根据截图和 `send-*.bin` 原始响应核对页面状态及发送结果。原始响应保存由 `general.save_raw_responses` 控制。
5. 环境修复后执行 `check` 或 `--dry-run`，根据验证结果恢复账号或调度。

### 常见故障

| 现象 | 诊断及处理 |
| --- | --- |
| 环境检查失败 | 核对所用 Python、虚拟环境、依赖、浏览器路径及目录权限 |
| 浏览器启动失败 | 查询实际启动日志，核对浏览器系统依赖和 DISPLAY/Xvfb 配置 |
| 登录记录缺失或失效 | 使用原账号用户数据目录和代理重新登录 |
| 出口 IP 或代理不一致 | 核对网络配置并重新建立登录基线 |
| 会话定位失败 | 核对截图、页面状态、`selectors.py` 及会话定位实现 |
| 发送回执未确认 | 查询当前会话和原始响应，保留账本保护记录 |
| 任务资源占用 | 查询活动任务，等待完成或取消所属任务 |
| 服务恢复后的执行延迟 | 核对计划开关、时区、随机延迟和调度器实际触发时间 |
| HTTP 426 | 核对 HTTPS 终止和可信代理配置 |
| HTTP 403 来源校验失败 | 核对 Host、转发协议、外部端口及 `origin_rejected` 日志，参见 [HTTPS 配置](cloud.md#https-反向代理) |
| Docker 登录端口占用 | 使用控制面板登录，或停止占用端口的容器后启动独立登录服务 |
| 通知凭据保存被拒绝或更新未生效 | 核对进程环境优先级，修改 Compose 环境配置后重建容器，参见 [凭据管理](cloud.md#通知凭据管理) |

通知缺失不构成任务成功依据。日志、截图和原始响应可能包含账号信息，应控制访问权限。健康状态更新不解除未确认发送结果限制；相关账本、运行日志和截图应按各自保留策略备份。
